# Сбалансированное обучение KoKs

Документация системы обучения, проверки качества данных, управления весами модели и совместимости токенизаторов проекта **KoKs**.

Система предназначена для контролируемого обучения модели с защитой от накопления ошибочных данных, ухудшения качества ответов и случайного изменения рабочих весов.

## Основные изменения

Система обучения KoKs использует контролируемый подход к изменению весов модели.

Основные изменения:

- Автоматическое обучение отключено по умолчанию.
- Выполнение произвольного Python-кода отключено.
- Автоматическое выполнение изменяющих системных команд из ответов модели заблокировано.
- Новые обучающие данные требуют проверки.
- Исправления пользователя имеют приоритет перед непроверенными ответами.
- Обучение использует постоянный контрольный набор.
- Новая модель принимается только при улучшении контрольной ошибки.
- При неудачном обучении исходные веса восстанавливаются.
- Поддерживается совместимость со старыми токенизаторами и чекпоинтами.

### Настройки безопасности

| Параметр | Значение | Назначение |
|---|---|---|
| `LIFE_AUTOLEARN_EVERY` | `0` | Отключает автоматическое обучение |
| `ALLOW_CODE_EXECUTION` | `False` | Запрещает произвольное выполнение Python |
| `LIFE_MIN_GOOD_PAIRS` | Настраивается | Минимум новых проверенных примеров для автообучения |
| `LIFE_MAX_TRAIN_TEXTS` | Настраивается | Ограничивает объём обучающих данных |

Рабочая директория subprocess не является полноценной изоляцией операционной системы.

Чтение информации и поиск остаются доступными через соответствующие инструменты.

## Источники обучающих данных

KoKs разделяет проверенные и непроверенные данные.

Это предотвращает автоматическое включение случайной информации из интернета или ответов модели в обучающий набор.

### Файлы данных

| Файл | Назначение |
|---|---|
| `data/learning_records.json` | Записи обучения и веб-кандидаты |
| `data/teacher_dialogs.txt` | Подготовленные обучающие диалоги |
| `data/dialogs.txt` | Исторические диалоги для поиска ответов |
| `data/validation.json` | Постоянный контрольный набор |

### Непроверенные данные

Записи из режима `/teach` и фрагменты веб-страниц сохраняются в:

```text id="yp5x81"
data/learning_records.json
```

Каждая запись содержит:

- Источник информации.
- Дату создания.
- Уникальный идентификатор.
- Статус проверки `verified: false`.

Непроверенные записи не используются автоматически как достоверные обучающие примеры.

### Проверенные данные

Пользователь может исправить ответ модели командой:

```text id="onvjf5"
правильно <проверенный ответ>
```

После подтверждения исправление сохраняется как проверенное пользователем.

Правила обработки:

1. Пустые исправления отклоняются.
2. Проверенное исправление имеет приоритет над непроверенными данными.
3. Последнее проверенное исправление считается актуальным.
4. Непроверенные веб-кандидаты не становятся обучающей истиной автоматически.

### Проверка веб-кандидата

Для подтверждения информации, полученной из интернета:

1. Задайте соответствующий вопрос в чате.
2. Проверьте полученную информацию.
3. Введите команду исправления с достоверным ответом.

Пример:

```text id="j9jj1s"
Пользователь: Что такое Python?

KoKs: Python — язык программирования.

Пользователь: правильно Python — высокоуровневый язык программирования общего назначения.
```

Подтверждённое исправление может использоваться в последующем обучении.

## Проверка и подтверждение данных

### Обучение через чат

Для записи обучающих диалогов используются команды:

| Команда | Назначение |
|---|---|
| `/teach` | Начать запись диалогов |
| `/stop-teach` | Остановить запись |
| `/train-now` | Запустить контролируемое обучение |

### Источники для /train-now

Команда:

```text id="jkw30s"
/train-now
```

Использует:

- Проверенные исправления пользователя.
- Данные из `data/teacher_dialogs.txt`.

Файл `data/dialogs.txt` продолжает использоваться для поиска ответов, но не считается автоматически проверенным источником для `/train-now`.

Перед повторным использованием исторических диалогов рекомендуется удалить ошибочные, устаревшие и противоречивые ответы.

### Ручное обучение через CLI

```bash id="05ax1p"
python main.py --train data/dialogs.txt --epochs 10
```

При явном запуске `--train` указанный файл считается подготовленным пользователем обучающим материалом.

Проверка содержимого такого файла является ответственностью пользователя.

## Контроль качества обучения

Перед изменением весов модель проходит проверку на постоянном контрольном наборе.

### Минимальные требования

| Параметр | Значение |
|---|---|
| Минимум разных вопросов | 10 |
| Доля контрольных примеров | 10% |
| Минимум контрольных примеров | 2 |
| Контрольный файл | `data/validation.json` |
| Условие принятия модели | Строгое снижение средней ошибки |

Для первого обучения требуется не менее 10 различных вопросов.

### Контрольный набор

Контрольные данные сохраняются в:

```text id="8y74mt"
data/validation.json
```

Файл остаётся постоянным между сессиями обучения.

Контрольные вопросы, включая варианты с исправленными ответами, исключаются из обучающих данных, используемых для изменения весов.

### Формат validation.json

Файл можно подготовить вручную в формате JSON-массива строк.

Каждая строка содержит вопрос и ответ, разделённые символом новой строки.

Пример:

```json id="j7o4v0"
[
  "Что такое Python?\nPython — язык программирования.",
  "Что такое ИИ?\nИИ — технология создания систем, выполняющих интеллектуальные задачи."
]
```

Этот пример показывает формат файла, но не является достаточным контрольным набором для полноценной оценки качества.

### Рекомендуемое содержимое контрольного набора

Для содержательной проверки рекомендуется включать:

- Вопросы на ранее изученные знания.
- Вопросы с новыми формулировками.
- Исправленные ответы.
- Команды управления.
- Вопросы, на которые модель должна отказаться отвечать.
- Проверку сохранения ранее изученной информации.

Минимум из двух контрольных примеров недостаточен для надёжной оценки поведения модели.

Не удаляйте `data/validation.json` между сессиями, если необходимо сохранять сопоставимость результатов.

## Сохранение и восстановление модели

Каждый запуск обучения сравнивает исходную модель и нового кандидата.

### Алгоритм проверки

1. Сохраняются исходные веса модели.
2. Вычисляется средняя ошибка исходной модели на контрольных токенах.
3. Выполняется обучение кандидата.
4. После эпох оценивается контрольная ошибка.
5. Выбирается лучшая эпоха.
6. Новые веса принимаются только при строго меньшей средней ошибке.
7. При отказе или ошибке исходные веса восстанавливаются.

### Условие принятия

Новая модель принимается только при выполнении условия:

```text id="27ab8n"
candidate_validation_loss < original_validation_loss
```

Если контрольная ошибка не уменьшилась, исходная модель сохраняется.

### Защита чекпоинтов

При успешном обучении:

- Выбираются веса лучшей принятой эпохи.
- Чекпоинт сначала записывается во временный файл.
- Выполняется атомарная замена рабочего чекпоинта.
- Предыдущая рабочая версия сохраняется с суффиксом `.previous`.
- В оперативную память возвращаются веса принятой лучшей эпохи.

При исключении, отказе или ошибке сохранения выполняется восстановление исходных весов.

### Ограничения оценки

Снижение средней ошибки на контрольном наборе не гарантирует:

- Улучшение каждого отдельного ответа.
- Сохранение всех ранее изученных знаний.
- Корректность выполнения команд.
- Безопасность инструментов.
- Отсутствие ошибочных ответов.

Перед включением автономного изменения весов необходимы дополнительные поведенческие тесты и ручная проверка.

Постоянный контрольный набор не следует бесконечно использовать как единственное доказательство улучшения качества.

## Новые данные и повторение

KoKs использует механизм повторения ранее изученных примеров для уменьшения риска забывания старой информации.

### Пропорции обучающих данных

При наличии ранее выученных примеров используется ориентировочное соотношение:

| Тип данных | Доля |
|---|---|
| Новые проверенные примеры | 20% |
| Ранее изученные примеры | 80% |

Если старых примеров недостаточно, количество новых примеров уменьшается для соблюдения баланса.

При первом обучении используются доступные проверенные данные.

### Выбор примеров

- Новые примеры выбираются с конца списка.
- Старые примеры перемешиваются.
- Общий объём ограничивается `LIFE_MAX_TRAIN_TEXTS`.
- Для автообучения требуется минимум `LIFE_MIN_GOOD_PAIRS` новых проверенных примеров.
- Непроверенные веб-кандидаты не учитываются при выполнении этого условия.

### Учёт обученных данных

Счётчик:

```text id="xj4v2d"
trained
```

Увеличивается только для примеров, участвовавших в принятом обучении.

Если обучение отклонено, примеры не считаются успешно изученными.

### Рекомендации по обучению

- Проверяйте новые данные перед обучением.
- Не увеличивайте количество эпох вместо улучшения качества данных.
- Сохраняйте баланс между новыми и старыми примерами.
- Следите за контрольной ошибкой.
- Проверяйте ранее изученные знания после обучения.

## Токенизатор и совместимость

KoKs поддерживает новые и старые форматы токенизации.

### Новый формат

Новые токенизаторы используют специальный токен:

```text id="j57ohq"
<SEP>
```

Он обозначает границы строк.

Запрос генерации не заканчивается токеном:

```text id="91p6r7"
<EOS>
```

### Совместимость со старыми моделями

Старые токенизаторы без поля:

```text id="orvnyc"
format_version
```

Загружаются в прежнем формате, соответствующем версии 1.

При этом:

- Старое кодирование токенов сохраняется.
- Кодирование весов не изменяется автоматически.
- Новый формат не применяется к старой модели без отдельного обучения.

Для перехода старой модели на новый формат необходимо отдельное обучение.

### Проверка чекпоинтов

Новые чекпоинты содержат отпечаток токенизатора.

При загрузке проверяется соответствие токенизатора сохранённой модели.

Если отпечатки не совпадают, загрузка блокируется.

Для старых чекпоинтов без отпечатка проверяются:

- Версия формата.
- Размер словаря.

Это предотвращает загрузку весов с несовместимым кодированием токенов.

## Тестирование

### Запуск тестов

```bash id="m7tvs7"
python -m unittest discover -s tests -v
```

### Особенности тестирования

Исходные smoke-тесты могут создавать или изменять состояние приложения.

Для сохранения рабочих журналов, памяти и других данных рекомендуется запускать полный набор тестов на копии проекта.

Тесты нового механизма обучения используют:

- Небольшую CPU-модель.
- Временные директории.
- Изолированные тестовые данные.

### Что необходимо проверять

- Сохранение проверенных исправлений.
- Исключение непроверенных данных из обучения.
- Создание постоянного контрольного набора.
- Исключение контрольных вопросов из обучающих примеров.
- Принятие модели только при снижении ошибки.
- Восстановление исходных весов при отказе.
- Сохранение предыдущего чекпоинта.
- Совместимость старых токенизаторов.
- Блокировку несовместимых чекпоинтов.
- Корректное обновление счётчика `trained`.

## Рекомендации

Для стабильного и контролируемого обучения:

1. Используйте только проверенные обучающие данные.
2. Сохраняйте постоянный контрольный набор.
3. Не обучайте модель автоматически на непроверенных веб-страницах.
4. Проверяйте качество ответов после каждого обучения.
5. Сохраняйте резервные копии рабочих чекпоинтов.
6. Не включайте выполнение произвольного Python-кода без полноценной изоляции.
7. Не включайте автономное изменение весов без дополнительных тестов.
8. Проверяйте сохранение ранее изученных знаний.
9. Не используйте контрольную ошибку как единственный показатель качества.
10. Перед обновлением токенизатора проверяйте совместимость с сохранённой моделью.

## Итог

Система сбалансированного обучения KoKs предназначена для контролируемого обновления модели с проверкой новых данных и сохранением ранее изученной информации.

Основные принципы:

- Проверка данных перед обучением.
- Разделение проверенных и непроверенных источников.
- Сохранение постоянного контрольного набора.
- Сравнение исходной и новой модели.
- Восстановление весов при неудачном обучении.
- Совместимость с предыдущими форматами модели.
- Ограничение автономного изменения весов.

**Основная цель — улучшать модель без автоматического принятия недостоверных данных и без необоснованной замены рабочих весов.**
