# KoKs

**KoKs** — локальный русскоязычный ИИ-ассистент с памятью, базой знаний, инструментами компьютера, собственной Transformer-моделью и автономным циклом жизни.

Проект оптимизирован для систем с **16 ГБ RAM и 6 ГБ VRAM (NVIDIA RTX 3050 Laptop GPU)** и предусматривает многоуровневую систему защиты.

> Обновлённый порядок обучения и ограничения описаны в [BALANCED_LEARNING.md](BALANCED_LEARNING.md).
>
> Автоматическое обучение весов и выполнение Python-кода отключены по умолчанию.

## Возможности

- Собственная Transformer-модель с BPE-токенизатором.
- Поддержка русского языка и семантического поиска.
- Локальная база знаний и память.
- Обучение на диалогах и исправление ответов.
- Поиск информации в интернете и чтение веб-страниц.
- Автономный цикл жизни с постановкой целей.
- Локальный HTTP API.
- Многоуровневый контроль файловых и системных операций.
- Поддержка CUDA и CPU.
- Настройки для оборудования с ограниченной памятью.

## Системные требования

| Компонент | Требование |
|---|---|
| Python | 3.10+ |
| PyTorch | CUDA или CPU |
| RAM | 16 ГБ |
| VRAM | 6 ГБ |
| GPU | NVIDIA RTX 3050 Laptop или совместимый |
| Дополнительно | `psutil` (опционально) |

## Установка

### 1. Установите PyTorch

Пример установки CUDA-сборки:

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124
```

> Убедитесь, что выбранная сборка PyTorch совместима с вашей версией Python, видеокартой и драйвером NVIDIA.

### 2. Установите зависимости

```bash
pip install psutil tqdm numpy
```

### 3. Проверьте доступность GPU

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

Если результат `True`, PyTorch обнаружил CUDA-устройство.

## Безопасность

KoKs предусматривает закрытый режим работы и централизованную проверку потенциально опасных операций.

Основные компоненты:

- `tools/security.py` — контроль операций.
- `config.py` — параметры безопасности.
- `SecurityManager` — ограничения, счётчики и блокировки.

### Настройки по умолчанию

| Параметр | Значение |
|---|---|
| `SAFE_MODE` | `True` |
| `SANDBOX_MODE` | `True` |
| `READ_ONLY_MODE` | `False` |
| `ALLOW_COMMAND_EXECUTION` | `False` |
| `ALLOW_DELETE_ANY` | `False` |
| `ALLOW_WRITE_OUTSIDE_BASE` | `False` |
| `ALLOW_EXTERNAL_PATHS` | `False` |
| `ALLOW_NETWORK` | `True` |
| `ALLOW_CODE_EXECUTION` | `False` |

### Заблокированные операции

При стандартной конфигурации отключены:

- `execute_command` — выполнение системных команд.
- `delete_file` — удаление файлов.
- `удали файл` и `удали папку`.
- `открой файл` и `открой папку` через ОС.
- `выполни команду`.
- Чтение и запись вне разрешённой области проекта.

### Запрещённые системные пути

```text
C:\Windows
C:\Program Files
C:\ProgramData
/etc
/usr
/bin
```

Дополнительно фильтруются части путей:

```text
system32
syswow64
appdata
recycle.bin
```

Запрещённые имена файлов:

```text
ntuser.dat
sam
security
hosts
id_rsa
```

Запрещённые расширения:

```text
.exe
.bat
.cmd
.ps1
.dll
.reg
```

### Уровни защиты

**1. Config.can_read / can_write / can_delete**

Проверяют:

- Путь к файлу.
- Расширение файла.
- Наличие запрещённых компонентов пути.
- Принадлежность к директории проекта.
- Соответствие белому списку.

**2. Config.can_execute_command**

Использует белый список префиксов:

```text
dir
ls
cat
echo
```

Блокирует опасные конструкции:

```text
rm -rf
format
reg delete
shutdown
takeown
icacls
powershell -enc
iex(
sudo
passwd
useradd
```

Также блокируются специальные операторы командной оболочки:

```text
;
&&
||
|
>
<
`
$(
```

> Даже команды из белого списка недоступны, пока `ALLOW_COMMAND_EXECUTION = False`.

**3. Config.can_execute_code**

Фильтрует потенциально опасные вызовы:

```python
shutil.rmtree
os.remove
os.system
subprocess
eval
exec
compile
__import__
pickle.loads
socket.socket
ctypes
Path.home
expanduser
sys.exit
```

При разрешённом выполнении кода рабочая директория — `sandbox/`.

**4. SecurityManager**

Обеспечивает:

- Счётчики записей, удалений, команд и выполнения кода.
- Ограничение операций через `MAX_OPERATIONS_PER_MINUTE`.
- Блокировку при подозрительной активности через `SUSPICIOUS_ACTIONS_TO_LOCK`.
- Сохранение состояния в `security_state.json`.
- Подтверждение опасных действий через `REQUIRE_CONFIRMATION_CODE`.

### Журнал безопасности

Отказы и подозрительные действия регистрируются в:

```text
logs/security.log
```

Уровни сообщений: `WARN` и `ERROR`.

### Команды безопасности

| Команда | Назначение |
|---|---|
| `/security` | Отчёт о состоянии защиты |
| `/lock` | Заблокировать операции |
| `/unlock` | Снять блокировку |

### Проверка безопасности

```bash
python main.py --security-report
```

Команда выводит текущие параметры `Config` и счётчики `SecurityManager`.

### Рекомендации

- Не запускайте ассистента с правами администратора.
- Не включайте `ALLOW_COMMAND_EXECUTION` без дополнительной изоляции.
- Не включайте `ALLOW_DELETE_ANY`.
- Не отключайте `SANDBOX_MODE`.
- Проверяйте журнал при подозрительной активности.

**Важно:** фильтрация строк, ограничение путей и рабочая директория `sandbox/` сами по себе не обеспечивают полноценную изоляцию операционной системы.

## Понимание вопросов

KoKs использует семантическую обработку текста для поиска подходящих ответов.

### Возможности обработки

- Стемминг русских и английских слов.
- Обработка синонимов.
- Определение типа вопроса.
- TF-IDF-оценка релевантности.
- Фильтрация навигационного и служебного текста.

Примеры синонимов:

```text
ИИ = искусственный интеллект = AI
Python = питон
```

Типы вопросов:

| Вопрос | Тип |
|---|---|
| Что такое X? | Определение |
| Как сделать X? | Инструкция |
| Почему X? | Причина |

### Источники ответов

Поиск выполняется последовательно:

1. Точное совпадение в `dialogs.txt` и `teacher_dialogs.txt`.
2. Семантический поиск по диалогам.
3. Семантический поиск по базе знаний.

## Обучение модели

### Запуск обучения

```bash
python main.py --train data/dialogs.txt --epochs 10
```

### Архитектура Transformer

| Параметр | Значение |
|---|---|
| `d_model` | 320 |
| `n_layers` | 6 |
| `n_heads` | 8 |
| `d_ff` | 1280 |
| `vocab_size` | 24000 |
| `max_len` | 512 |

### Оптимизация под RTX 3050 6 ГБ

| Параметр | Значение |
|---|---|
| `TRAIN_BATCH_SIZE` | 16 |
| `TRAIN_MAX_LEN` | 192 |
| AMP | bf16 |

> Фактическое потребление памяти зависит от реализации модели, оптимизатора и доступных возможностей GPU. Поддержку bf16 необходимо проверять для конкретного устройства.

### Оценка ресурсов

```python
from config import Config

print(Config.estimate_model_size_mb())
print(Config.estimate_training_peak_mb())
print(Config.estimate_inference_peak_mb())
print(Config.estimate_free_vram_after_training())

print(Config.validate())
print(Config.summary())
print(Config.memory_report())
print(Config.security_report())
```

### Обучение через диалог

| Команда | Описание |
|---|---|
| `/teach` | Начать запись обучающих диалогов |
| `/stop-teach` | Остановить запись |
| `/train-now` | Запустить дообучение модели |

Исправление ответа:


## Автономная жизнь

KoKs содержит автономный цикл, в котором агент может формировать цели, искать информацию и сохранять кандидатов для последующей проверки.

### Запуск

```bash
python main.py --life
```

Запуск с ограничением количества шагов:

```bash
python main.py --life --life-steps 100
```

### Возможности

- Самостоятельная постановка целей.
- Поиск информации в интернете.
- Чтение веб-страниц.
- Извлечение потенциально полезных знаний.
- Сохранение кандидатов на обучение.
- Ведение журнала действий.

Автоматическое изменение весов модели **отключено по умолчанию**.

### Файлы состояния

| Файл | Назначение |
|---|---|
| `life/state/journal.jsonl` | Журнал автономной активности |
| `life/state/goals.json` | Цели агента |
| `learning_records.json` | Кандидаты для обучения |

### Разрешённые операции

- Поиск и чтение информации в интернете.
- Запись в разрешённые директории проекта.
- Работа с памятью и базой знаний.
- Дообучение при соответствующем разрешении.

Разрешённые пути записи:

```text
life/state/**
data/**
knowledge.json
memory.json
models/*
```

### Запрещённые операции

- Выполнение системных команд.
- Удаление файлов.
- Запись вне разрешённых путей.
- Использование отключённых инструментов.

### Лимиты автономного режима

| Параметр | Назначение |
|---|---|
| `LIFE_STEP_PAUSE_SEC` | Пауза между шагами |
| `LIFE_SLEEP_EVERY_STEPS` | Частота длительных пауз |
| `LIFE_SLEEP_SEC` | Продолжительность сна |
| `LIFE_MAX_STEPS_PER_SESSION` | Максимум шагов за сессию |
| `LIFE_AUTOLEARN_EVERY` | Интервал проверки самообучения |
| `LIFE_MAX_GOALS` | Максимум целей |
| `LIFE_JOURNAL_KEEP` | Ограничение журнала |
| `LIFE_MAX_TRAIN_TEXTS` | Максимум обучающих текстов |

### Фильтрация обучающих пар

Перед сохранением веб-кандидата в `learning_records.json` с `verified=false` выполняются проверки:

- Вопрос не является служебным словом.
- Вопрос не содержит маркеров ошибок.
- Ответ не является навигацией сайта.
- Ответ содержит связный текст.
- Пары с одинаковыми вопросами не дублируются.

### Извлечение ответов

Алгоритм обработки веб-страницы:

1. Разбивает текст страницы на предложения.
2. Извлекает ключевые слова вопроса.
3. Ищет наиболее релевантное предложение.
4. Добавляет следующее предложение для контекста.
5. Ограничивает результат до 600 символов.

## Совместимость чекпоинтов

При загрузке сохранённой модели её архитектурные параметры читаются из чекпоинта.

Используется функция:

```python
read_checkpoint_shape
```

Расположение:

```text
core/trainer.py
```

Поддерживаемые параметры:

```text
vocab_size
d_model
n_heads
n_layers
d_ff
max_len
```

Это позволяет определять конфигурацию модели по сохранённому чекпоинту.

## Статус проекта

KoKs — локальный ИИ-проект с экспериментальными возможностями обучения и автономного поведения.

Качество ответов зависит от обучающих данных, содержимого базы знаний и состояния модели. Наличие семантического поиска и автономного цикла не гарантирует правильность ответов или достоверность информации, полученной из интернета.

**Рекомендуется проверять обучающие данные перед дообучением и сохранять резервные копии чекпоинтов.**
