# KoKs

**KoKs** — локальный русскоязычный ИИ-ассистент с памятью, базой знаний, инструментами компьютера, собственной Transformer-моделью и автономным циклом жизни.

Проект оптимизирован для систем с 16 ГБ оперативной памяти и 6 ГБ видеопамяти (NVIDIA RTX 3050 Laptop GPU).

Включает многоуровневую систему безопасности, семантический поиск, обучение на диалогах и инструменты автономной работы.

> Обновлённый порядок обучения и ограничения описаны в [BALANCED_LEARNING.md](BALANCED_LEARNING.md).
>
> Автоматическое обучение весов и выполнение Python-кода отключены по умолчанию.

## Возможности

- Собственная Transformer-модель с BPE-токенизатором.
- Поддержка русского языка.
- Семантический поиск по диалогам и базе знаний.
- Краткосрочная память и сохранение информации.
- Обучение на текстовых данных и диалогах.
- Исправление ответов через интерактивный режим.
- Поиск информации в интернете.
- Чтение и анализ веб-страниц.
- Автономная постановка целей.
- Локальный HTTP API.
- Контроль файловых и системных операций.
- Поддержка CUDA и CPU.
- Оптимизация использования оперативной и видеопамяти.

## Установка

### Установка PyTorch

Для систем с поддерживаемой NVIDIA CUDA:

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124
```

Убедитесь, что выбранная версия PyTorch совместима с вашей видеокартой, драйвером и версией Python.

### Установка зависимостей

```bash
pip install psutil tqdm numpy
```

### Проверка CUDA

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

Если команда возвращает `True`, PyTorch обнаружил доступное CUDA-устройство.

## Безопасность

KoKs работает с централизованной системой проверки потенциально опасных операций.

Основные компоненты:

- `tools/security.py` — контроль операций.
- `config.py` — конфигурация безопасности.
- `SecurityManager` — управление ограничениями, счётчиками и блокировками.

### Настройки по умолчанию

| Параметр | Значение |
|---|---|
| `SAFE_MODE` | `True` |
| `SANDBOX_MODE` | `True` |
| `READ_ONLY_MODE` | `False` |
| `ALLOW_COMMAND_EXECUTION` | `False` |
| `ALLOW_DELETE_ANY` | `False` |
| `ALLOW_WRITE_OUTSIDE_BASE` | `False` |
| `ALLOW_EXTERNAL_PATHS` | `False` |
| `ALLOW_NETWORK` | `True` |
| `ALLOW_CODE_EXECUTION` | `False` |

### Запрещённые операции

При стандартной конфигурации отключены:

- `execute_command` — выполнение системных команд.
- `delete_file` — удаление файлов.
- `удали файл` и `удали папку`.
- `открой файл` и `открой папку` через операционную систему.
- `выполни команду`.
- Чтение и запись вне разрешённых директорий проекта.

### Запрещённые системные пути

```text
C:\Windows
C:\Program Files
C:\ProgramData
/etc
/usr
/bin
```

Дополнительно фильтруются следующие части путей:

```text
system32
syswow64
appdata
recycle.bin
```

Запрещённые имена файлов:

```text
ntuser.dat
sam
security
hosts
id_rsa
```

Запрещённые расширения:

```text
.exe
.bat
.cmd
.ps1

```

### Уровни защиты

#### Config.can_read / can_write / can_delete

Проверяют:

- Путь к файлу.
- Расширение файла.
- Наличие запрещённых компонентов пути.
- Принадлежность файла к директории проекта.
- Соответствие разрешённым путям и белому списку.

#### Config.can_execute_command

Использует белый список префиксов:

```text
dir
ls
cat
echo
```

Блокирует потенциально опасные команды:

```text
rm -rf
format
reg delete
shutdown
takeown
icacls
powershell -enc
iex(
sudo
passwd
useradd
```

Также запрещены операторы командной оболочки:

```text
;
&&
||
|
>
<
`
$(
```

Даже команды из белого списка недоступны, пока `ALLOW_COMMAND_EXECUTION = False`.

#### Config.can_execute_code

Фильтрует потенциально опасные вызовы:

```python
shutil.rmtree
os.remove
os.system
subprocess
eval
exec
compile
__import__
pickle.loads
socket.socket
ctypes
Path.home
expanduser
sys.exit
```

При разрешённом выполнении Python-кода используется рабочая директория `sandbox/`.

#### SecurityManager

Обеспечивает:

- Учёт операций записи, удаления, выполнения команд и кода.
- Ограничение количества операций через `MAX_OPERATIONS_PER_MINUTE`.
- Блокировку после подозрительных попыток через `SUSPICIOUS_ACTIONS_TO_LOCK`.
- Сохранение состояния в `security_state.json`.
- Подтверждение опасных действий через `REQUIRE_CONFIRMATION_CODE`.

### Журнал безопасности

Отказы и подозрительные действия регистрируются в файле:

```text
logs/security.log
```

Используемые уровни сообщений:

- `WARN`
- `ERROR`

### Команды безопасности

| Команда | Назначение |
|---|---|
| `/security` | Показать отчёт безопасности |
| `/lock` | Заблокировать операции |
| `/unlock` | Снять блокировку |

### Проверка безопасности

```bash
python main.py --security-report
```

Команда выводит текущие параметры `Config` и счётчики `SecurityManager`.

### Рекомендации по безопасности

- Не запускайте ассистента от имени администратора.
- Не включайте `ALLOW_COMMAND_EXECUTION` без дополнительной изоляции.
- Не включайте `ALLOW_DELETE_ANY`.
- Не отключайте `SANDBOX_MODE`.
- Регулярно проверяйте журнал безопасности.
- Используйте резервные копии важных файлов.

Фильтрация строк и ограничение рабочих директорий не заменяют полноценную изоляцию операционной системы.

## Понимание вопросов

KoKs использует семантическую обработку текста для поиска релевантных ответов.

### Обработка текста

- Стемминг русских и английских слов.
- Обработка синонимов.
- Определение типа вопроса.
- TF-IDF-оценка релевантности.
- Удаление навигационного и служебного текста из ответов.

Примеры синонимов:

```text
ИИ = искусственный интеллект = AI
Python = питон
```

### Определение типа вопроса

| Вопрос | Тип |
|---|---|
| Что такое X? | Определение |
| Как сделать X? | Инструкция |
| Почему X? | Причина |

### Источники ответов

Поиск выполняется в следующем порядке:

1. Точное совпадение в `dialogs.txt` и `teacher_dialogs.txt`.
2. Семантический поиск по диалогам.
3. Семантический поиск по базе знаний.

## Автономный режим

KoKs включает автономный цикл работы, в котором агент может самостоятельно формировать цели, искать информацию и сохранять кандидатов для последующей проверки.

### Запуск

```bash
python main.py --life
```

Запуск с ограничением количества шагов:

```bash
python main.py --life --life-steps 100
```

### Возможности

- Самостоятельная постановка целей.
- Поиск информации в интернете.
- Чтение веб-страниц.
- Извлечение потенциально полезных знаний.
- Сохранение кандидатов для обучения.
- Ведение журнала активности.

Автоматическое изменение весов модели отключено по умолчанию.

### Файлы состояния

| Файл | Назначение |
|---|---|
| `life/state/journal.jsonl` | Журнал автономной активности |
| `life/state/goals.json` | Цели агента |
| `learning_records.json` | Кандидаты для обучения |

### Разрешённые операции

- Поиск и чтение информации в интернете.
- Запись в разрешённые директории проекта.
- Работа с памятью и базой знаний.
- Дообучение модели при соответствующем разрешении.

Разрешённые пути записи:

```text
life/state/**
data/**
knowledge.json
memory.json
models/*
```

### Запрещённые операции

- Выполнение системных команд.
- Удаление файлов.
- Запись вне разрешённых директорий.
- Использование отключённых инструментов.

### Лимиты автономного режима

| Параметр | Назначение |
|---|---|
| `LIFE_STEP_PAUSE_SEC` | Пауза между шагами |
| `LIFE_SLEEP_EVERY_STEPS` | Частота длительных пауз |
| `LIFE_SLEEP_SEC` | Продолжительность паузы |
| `LIFE_MAX_STEPS_PER_SESSION` | Максимальное количество шагов |
| `LIFE_AUTOLEARN_EVERY` | Интервал проверки самообучения |
| `LIFE_MAX_GOALS` | Максимальное количество целей |
| `LIFE_JOURNAL_KEEP` | Ограничение размера журнала |
| `LIFE_MAX_TRAIN_TEXTS` | Максимальное количество обучающих текстов |

### Фильтрация обучающих пар

Перед сохранением веб-кандидата в `learning_records.json` с параметром `verified=false` выполняются проверки:

- Вопрос не является служебным словом.
- Вопрос не содержит маркеров ошибок.
- Ответ не является навигацией сайта.
- Ответ содержит связный текст.
- Пары с одинаковыми вопросами не дублируются.

### Извлечение ответов со страниц

Алгоритм обработки:

1. Страница разбивается на предложения.
2. Из вопроса извлекаются ключевые слова.
3. Выполняется поиск наиболее релевантного предложения.
4. Добавляется следующее предложение для контекста.
5. Результат ограничивается 600 символами.


```text

```

Поддерживаемые параметры:

```text
vocab_size
d_model
n_heads
n_layers
d_ff

```

Это позволяет определять конфигурацию модели по сохранённому чекпоинту.
